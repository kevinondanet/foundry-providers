## Public C# API

- `EvalLogWriter.Write(log, path)` / `WriteAsync`: samples sorted as `sort_samples`, tags and metadata recomputed
  from the edits, then Python's exact `.json` format: snake_case names in pydantic field order, 2-space indent,
  `exclude_none`, non-ASCII verbatim, `datetime.isoformat()` timestamps (`+00:00`; pydantic's `Z` form where
  Python uses it: provenance and checkpoint `created_at`), and `NaN` / `Infinity` / `-Infinity` constants
  (`ser_json_inf_nan="constants"`) everywhere a float can appear, including inside raw JSON members.
- `EvalLogWriter.Read(path)` / `ReadAsync`, `Read(path, ResolveAttachments)`, `ReadHeader(path)`: `NaN` constants are
  tolerated (sentinel rewrite before strict parsing), legacy shapes are migrated (`results.scorer` + `metrics`,
  `sample.score`, `sample.transcript`, `results.sample_reductions`, `max_messages`, `stop_reason: "length"`,
  `[type, config]` sandbox, `tools`/`sandbox` log levels, `from_message`, null score values), a version above 2 is
  rejected with `InvalidDataException` and older versions are normalised to 2.
- `EvalLogWriter.Options`: the one read-only `JsonSerializerOptions`; usable for any member type (events, scores,
  messages, timelines, summaries).
- `EvalLogEditing.EditEvalLog(log, edits, provenance)`: no-op edits filtered, invalid edits rejected, tags sorted.
- `sample.Summary()` (`EvalSampleSummary`) and `LogThinning`: the `.eval` summary view.
- `LogAttachments.CondenseSample(sample, logImages)`, `CondenseEvent`, `ResolveSampleAttachments(sample, mode)`,
  `ResolveEventsAttachments`, `AttachmentRefs`, `IsDataUri`; `MurmurHash3.Hash(text)` produces the same keys as
  Python (verified against `log_images.json`).
- `Transcript` stamps `uuid`, `span_id` and `working_start` on every event it records.

## Deviations from Python, and why

- `TimelineEvent` keeps the event uuid rather than the event object (`Resolve(events)` looks it up); Python
  rejects a timeline whose uuid does not resolve, this port keeps it.
- `SandboxEvent` carries Python's fields (`cmd`, `options`, `file`, `input`, `result: int`, `output`); the
  pre-port `(action, input, result)` constructor is kept as a secondary constructor that maps the raw shapes.
- `EvalConfig` splits Python's unions into typed pairs (`Limit`/`LimitRange`, `FailOnError`/`FailOnErrorThreshold`,
  `SampleShuffle`/`SampleShuffleSeed`); `notification` and `acp_server` stay `object`.
- `ApprovalPolicyConfig`, `ViewerConfig`, `EvalSpec.metrics`, `EvalScorer.metrics`, `SampleInitEvent.state`,
  `events_data` and the RFC 6902 `changes` of `StateEvent`/`StoreEvent` are raw JSON (patching is another agent's).
- A log whose `eval_id` is empty gets a fresh short uuid on read; Python derives a stable `base57_id_hash`
  (blake2s) of run/task/created — no blake2s in the BCL, so ids of such (pre-2024) logs differ per read.
- `ToolCall.view` is not on the Provider `ToolCall`, so a tool-call view inside an assistant message is dropped on
  read; `ToolEvent.view` and `ApprovalEvent.view` are kept.
- `LogThinning.ThinText` breaks on whitespace only (Python's `textwrap.shorten` also breaks on hyphens); JSON size
  budgets count UTF-16 units where Python counts code points.
- `ScoreEdit` uses `Edited<T>` (unset = Python's `"UNCHANGED"`); a cleared field is written as absent, as Python
  does, and reads back as unchanged.
- Errors: malformed JSON is `JsonException`, a newer version `InvalidDataException`, invalid edits
  `ArgumentException` (Python `ValueError`), old+new legacy forms together `JsonException` (Python `TypeError`).
- Python's `Event` union has 23 members, not 22; all are ported.

## Not ported

- The message and call pools of condensed logs (`condense_events` / `expand_events`, `input_refs` / `call_refs`
  resolution, `CallWalkCache`): the references are read and written verbatim only.
- The `.eval` zip recorder, the realtime buffer, S3 ETags, `read_eval_log_sample*`, `timeline_build` / `render`,
  `SampleSerializationError` depth checks, `EvalSample.metadata_as` / `store_as`, `invalidate_samples`.
